# Сборка, установка и обновление

## Почему данные не теряются при обновлении

| Гарантия | Как обеспечено |
|---|---|
| Android считает новую сборку обновлением, а не другим приложением | `applicationId = com.viplayer.app` никогда не меняется |
| Обновление ставится поверх, без удаления | каждый APK подписан **одним и тем же** ключом; `build-apk.sh` отказывается собирать без него |
| Версия не «откатывается» | `deploy-all.sh` сам увеличивает build number (Android `versionCode`) |
| Схема БД обновляется корректно | миграции Drift + снапшоты схемы + тесты миграций |
| Сломанная сборка не попадает на устройства | `deploy-all.sh` прогоняет `flutter analyze` и `flutter test` перед установкой |
| Музыка переживает даже удаление приложения | загрузки лежат в `Music/ViPlayer`, а не в приватной папке |
| Скрипт никогда сам не удаляет приложение | при несовпадении подписи — остановка с объяснением |
| ПК: можно откатить БД | `backup-data.sh` перед каждой установкой, хранятся 10 последних копий |
| ПК: неудачная сборка не ломает установленную версию | бандл подменяется атомарно, только после успешной сборки |

## Один раз: ключ подписи

```bash
scripts/create-keystore.sh
```

Создаст `~/viplayer-release.jks` и `android/key.properties` (в `.gitignore`).

> ⚠️ **Сделайте резервную копию `~/viplayer-release.jks` и пароля.** Без них
> следующее обновление телефона будет возможно только через удаление приложения.

## Обновление

```bash
scripts/deploy-all.sh           # ПК + телефон
scripts/deploy-all.sh --linux   # только ПК
scripts/deploy-all.sh --phone   # только телефон
```

После обновления ПК перезапустите ViPlayer.

### Подключение телефона

- **USB:** включить «Отладку по USB» в настройках разработчика.
- **Wi-Fi (Android 11+):** Настройки разработчика → «Отладка по Wi-Fi» →
  «Подключить по коду», затем на ПК:
  ```bash
  adb pair <ip>:<порт-сопряжения>   # один раз, ввести код
  adb connect <ip>:<порт>
  ```

Без подключения скрипт просто соберёт APK и подскажет путь — его можно
скопировать на телефон и открыть вручную.

## Версии

`version: X.Y.Z+N` в `pubspec.yaml`. `N` растёт автоматически при каждом деплое
на телефон. Смысловую версию поднимайте вручную:

```bash
scripts/bump-version.sh patch   # исправления
scripts/bump-version.sh minor   # новые возможности
```

## Бэкапы

- **ПК:** `~/.local/share/viplayer-backups/<дата>/` — копия БД перед каждой
  установкой. Восстановление: закрыть ViPlayer, скопировать файлы обратно в
  `~/.local/share/com.viplayer.app/`.
- **Телефон:** приватные данные release-сборки по adb не читаются. Страховка —
  LAN-синхронизация (ПК хранит полную копию) и экспорт в файл из приложения
  *(появится вместе с синхронизацией)*.

## Несовпадение подписи (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`)

Значит, на телефоне стоит сборка, подписанная другим ключом (например, debug).
Скрипт **ничего не меняет**. Что делать:

1. Синхронизировать телефон с ПК (или сделать экспорт в приложении).
2. Удалить приложение на телефоне вручную, поставить новый APK.
3. Синхронизировать обратно. Музыка в `Music/ViPlayer` при этом не удаляется.

Это нужно максимум один раз — дальше все сборки подписаны одним ключом.

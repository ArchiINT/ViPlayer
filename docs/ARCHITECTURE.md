# Архитектура

## Стек

| Задача | Решение |
|---|---|
| UI | Flutter (Material 3, своя тёмная тема) |
| Состояние | Riverpod 3 (без кодогенерации) |
| Навигация | go_router, `StatefulShellRoute` — у каждой вкладки свой стек и скролл |
| База данных | Drift (SQLite) |
| Локализация | `flutter gen-l10n`, ARB-файлы в `lib/l10n/` |
| Воспроизведение *(этап 3)* | media_kit (libmpv) + audio_service (фон, уведомление, MPRIS) |
| Скачивание *(этапы 5–6)* | yt-dlp + ffmpeg на ПК, Dart-реализация на Android |

## Структура

```
lib/
  main.dart                 запуск: загрузка настроек, ProviderScope
  app.dart                  MaterialApp: тема, язык, роутер
  core/                     инфраструктура, не знает о конкретных экранах
    database/               Drift: tables.dart (схема), app_database.dart
    library/                медиатека: сканер, теги, обложки, отпечатки, репозиторий
    player/                 плеер: движок, очередь, сессия, системные медиаконтролы
    platform/               пути, особенности платформ
    router/                 маршруты и вкладки
    settings/               настройки устройства (язык, акцент)
    theme/                  цвета, шрифты, анимации, ThemeData
  features/<feature>/       одна папка на функцию: экраны, виджеты, логика
  shared/widgets/           переиспользуемые виджеты (оболочка, фон, стекло, строки…)
  shared/actions/           общие действия (например, «воспроизвести трек»)
  l10n/                     app_en.arb (шаблон), app_ru.arb; generated/ — не править
test/                       unit- и виджет-тесты; test/drift/ — тесты миграций
test/fixtures/audio/        маленькие аудиофайлы с тегами и обложками для тестов
integration_test/           на реальном приложении: плавность (scripts/perf-test.sh),
                            воспроизведение через настоящий движок (scripts/playback-test.sh)
drift_schemas/              снапшоты схемы БД по версиям (коммитятся)
scripts/                    сборка, установка, обновление, бэкап
docs/                       документация
```

Когда функция разрастается, внутри `features/<feature>/` появляются подпапки
`data/` (репозитории, DAO), `domain/` (модели, логика) и `presentation/`
(экраны, виджеты, провайдеры). Маленькие функции остаются плоскими.

### Правила зависимостей

- `features/*` → могут использовать `core/` и `shared/`.
- `core/` → не импортирует `features/` (исключение: `core/router` собирает экраны).
- Фичи не импортируют друг друга напрямую; общее выносится в `core/` или `shared/`.

## База данных

Схема — `lib/core/database/tables.dart`. Два вида таблиц:

| Таблица | Вид | Назначение |
|---|---|---|
| `tracks` | синхр. | песня: теги, источник, лайк, **fingerprint** |
| `playlists` | синхр. | плейлист, флаг «офлайн» |
| `playlist_entries` | синхр. | трек в плейлисте, дробная позиция |
| `play_events` | синхр. | история прослушиваний |
| `library_folders` | локальная | выбранные на этом устройстве папки |
| `track_files` | локальная | файл на этом устройстве → трек |

**Синхронизируемые** строки: UUID-ключ, `updated_at` (last-write-wins),
`deleted` (надгробие, чтобы удаление тоже синхронизировалось).
**Локальные** таблицы описывают только это устройство и никуда не отправляются.
Подробнее — [SYNC.md](SYNC.md).

Пути к файлам отделены от треков намеренно: один и тот же трек на ПК и телефоне
лежит по разным путям, но в БД это одна запись `tracks`.

### Изменение схемы

1. Изменить `tables.dart`.
2. Поднять `schemaVersion` и добавить шаг миграции в `app_database.dart`.
3. `scripts/db-schema.sh` — сохранит снапшот схемы и прогонит тесты миграций.
4. Закоммитить `drift_schemas/` и `test/drift/`.

База лежит в support-каталоге приложения (Linux: `~/.local/share/com.viplayer.app/`,
Android: приватное хранилище) и переживает обновления.

## Медиатека

`lib/core/library/`:

| Файл | Роль |
|---|---|
| `library_scanner.dart` | синхронизирует БД с файлами: находит, сравнивает по размеру/mtime, читает только новое и изменённое |
| `audio_files.dart` | обход папок и чтение тегов — чистый dart:io, работает в фоновых изолятах |
| `cover_store.dart` | обложки на диске, имя = хеш содержимого (одна обложка на альбом); `cover.jpg`/`folder.jpg` рядом с файлами как запасной вариант |
| `fingerprint.dart` | отпечаток трека для склейки дубликатов и синхронизации |
| `media_store.dart` + `MediaStoreChannel.kt` | Android: вся музыка устройства из MediaStore |
| `library_repository.dart` | запросы и папки |
| `library_models.dart` | `LibraryIndex`: альбомы, исполнители и поиск в памяти |
| `library_providers.dart` | провайдеры и `ScanController`: сканирование при старте, при изменении папок, слежение за папками на ПК |

Источники: выбранные папки + папка загрузок (всегда) + MediaStore (Android, переключатель).
Треки при пропаже файлов **не удаляются** — это синхронизируемые метаданные
(лайки, плейлисты); трек без локального файла просто не показывается.

## Плеер

`lib/core/player/`:

| Файл | Роль |
|---|---|
| `audio_backend.dart` | интерфейс движка + реализация на **media_kit (libmpv)**: без пауз между треками, любые форматы, один движок на Linux и Android |
| `player_service.dart` | очередь, управление, «играть следующим», сессия между запусками, исправление длительности |
| `audio_handler.dart` | системные медиаконтролы: уведомление и экран блокировки Android, MPRIS на Linux (медиаклавиши, `playerctl`, виджеты рабочего стола) |
| `player_providers.dart` | провайдеры для UI; `playerBootstrapProvider` восстанавливает сессию и держит очередь в актуальном состоянии |

Плеер создаётся в `main()` вне дерева виджетов — системные контролы управляют им,
даже когда экран не показан. Порядок воспроизведения (перемешивание, повтор)
ведёт сам движок — так переходы между треками остаются бесшовными.

- **«Предыдущий»** после 3 секунд воспроизведения возвращает в начало трека.
- **Сессия** (очередь, трек, позиция, повтор, громкость) сохраняется каждые 5 с и
  при смене трека; при запуске восстанавливается **на паузе**. Пропавшие файлы
  пропускаются.
- **Длительность:** если движок измерил длину, отличную от тегов больше чем на
  1,5 с, она записывается в БД.
- **UI:** мини-плеер (над навигацией / внизу контента), полноэкранный плеер
  (`/player`, обложка как фон), очередь (перетаскивание, смахивание для
  удаления), меню трека по долгому нажатию / правому клику.
- **Клавиатура (ПК):** пробел — пауза, ←/→ — перемотка на 5 с,
  Ctrl+←/→ — предыдущий/следующий.

## Плейлисты, «Понравившееся», история

`lib/core/library/collections_repository.dart` + `collections_providers.dart`.
Всё это — данные пользователя, синхронизируемые между устройствами, поэтому
каждая запись следует правилам синка: UUID, `updated_at` при каждом изменении,
удаление = «надгробие» `deleted`.

- **Лайк** — флаг на треке + `liked_at` (порядок в «Понравившемся»).
- **Плейлисты** — `playlists` + `playlist_entries`. Порядок — дробная позиция:
  перемещение меняет **одну** запись (позиция между соседями), поэтому правки
  на двух устройствах не конфликтуют. Если точность между соседями
  исчерпана — плейлист перенумеровывается. Трек в плейлисте один раз.
  Записи, чьих файлов нет на этом устройстве, хранятся, но не показываются.
- **Флаг «офлайн»** у плейлиста — для синка (его треки копируются на телефон).
- **История** — `play_events`, по записи на прослушивание. Засчитывает
  `PlayHistoryTracker` (`core/player/`): 30 с реального прослушивания или
  половина трека, если он короче; перемотка не считается; повтор трека —
  новое прослушивание. Каждая запись помечена `device_id` установки
  (`core/platform/device_id.dart`, случайный UUID).
- Общий SQL «трек + локальный файл + обложка» — `track_queries.dart`.

## Дизайн: «стекло»

- **Фон** — `AmbientBackground`: сильно «размытая» обложка (текущий трек, а на
  страницах альбома/исполнителя — их обложка) под тёмной вуалью; без обложки —
  мягкое свечение цвета акцента. Смена фона — плавный переход.
- **Панели** — `GlassPanel` / `GlassGroup`: полупрозрачный белый слой, тонкая
  обводка, скругления (`AppRadius`).
- **Акцент** — мягкие тона (`Accent`), выбирается в настройках.
- Шрифты вшиты: Inter (интерфейс), JetBrains Mono (длительности, пути),
  Orbitron (только логотип).
- Анимации — `AppMotion`: 150/250/600 мс, `easeOutCubic`.

### Правила производительности

Плавность — обязательное требование. Что соблюдаем:

- **Никаких живых размытий** (`BackdropFilter`, `ImageFiltered`): Impeller
  пересчитывает их каждый кадр. Эффект размытия фона получается растягиванием
  крошечной (12 px) копии обложки — бесплатно.
- **Никаких размытых теней в списках**; тень только у одиночных крупных обложек.
- Изображения декодируются в размере показа (`cacheWidth`).
- Списки — фиксированная высота строк (`itemExtent`), вкладки держатся в памяти
  (`AutomaticKeepAlive`).
- Частые обновления (прогресс сканирования, поток треков во время скана)
  прореживаются; индикатор сканирования не меняет раскладку.
- Проверка: `scripts/perf-test.sh <папка с музыкой>` — профильная сборка листает
  вкладки и списки и печатает время кадров. Цель: p99 построения и отрисовки
  < 16 мс, пропущенных кадров — 0.

## Локализация

- Языки: английский (по умолчанию) и русский; переключатель в настройках.
- Новые строки: добавить в `lib/l10n/app_en.arb` и `app_ru.arb`, затем
  `flutter gen-l10n` (или любой скрипт сборки).
- В коде: `AppLocalizations.of(context).someKey`. Строк прямо в виджетах нет.

## Соглашения по коду

- `flutter analyze` без замечаний — строгие правила в `analysis_options.yaml`.
- Форматирование — `dart format`.
- Комментарии и идентификаторы — на английском; документация — на русском.
- Новая логика сопровождается тестами (особенно БД, синхронизация, парсинг источников).

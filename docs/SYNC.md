# Синхронизация

> Статус: **спроектировано**, реализация — этап 7. Схема БД уже готова под неё.

## Цель

Как в YT Music: одна библиотека на ПК и телефоне — лайки, плейлисты, история,
сами треки. Без сервера: устройства общаются напрямую в локальной сети.

## Транспорт

- **Обнаружение:** UDP-броадкаст в локальной сети (как в Finanz).
- **Обмен:** HTTP между устройствами. Транспорт скрыт за интерфейсом, чтобы
  позже добавить другие (см. «В будущем»).

## Что синхронизируется

| Данные | Как |
|---|---|
| Треки (метаданные), лайки, плейлисты, история | автоматически, слиянием строк |
| Файлы: телефон → ПК | всё, что появилось на телефоне, копируется на ПК |
| Файлы: ПК → телефон | треки из «Понравившегося» и плейлистов с флагом **офлайн**; опция «копировать всё новое» |
| Остальная библиотека ПК | дома доступна на телефоне **стримингом по LAN**, без копирования |
| Удалённое скачивание | телефон отдаёт задачу ПК (yt-dlp), результат приходит синком |
| Папки, пути, настройки | **не** синхронизируются — они свои на каждом устройстве |

## Слияние

- У каждой синхронизируемой строки UUID, `updated_at` и `deleted`.
- Побеждает более позднее изменение (last-write-wins) построчно.
- Удаление = надгробие (`deleted = true`), чтобы оно дошло до другого устройства.
- Порядок в плейлистах — дробные позиции: перемещение трека меняет одну строку,
  поэтому правки на двух устройствах не конфликтуют.
- История — только добавление, конфликтов нет.

## Опознание трека на разных устройствах

Пути файлов на ПК и телефоне разные, поэтому трек опознаётся по **fingerprint**:

1. ISRC или ID источника (`youtube:<id>`, `soundcloud:<id>`), если известен;
2. иначе — нормализованные «исполнитель + название» + длительность (с точностью
   до пары секунд);
3. при передаче файлов дополнительно сверяется хеш содержимого.

Если на двух устройствах независимо появился один и тот же трек, записи
сливаются в одну.

## В будущем: синхронизация через интернет без своего сервера

Пока не делаем, но архитектура это допускает (новый транспорт, та же логика слияния):

- **Syncthing:** ViPlayer пишет снапшот изменений в общую с телефоном папку,
  Syncthing доставляет её и `Music/ViPlayer` через интернет.
- **Облачная папка** (Nextcloud / WebDAV) как «почтовый ящик» для снапшотов.
- Позже — небольшой собственный relay-сервер.
